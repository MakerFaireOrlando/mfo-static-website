A row in _data/schedule.json can carry a `url`, and each entry in its `guests[]` can carry one, pointing at an exhibit permalink. pages/schedule.md follows those forward. This include follows them BACKWARD so an exhibit page can say its maker is on the Main Stage at 1:30 on Saturday. The join has to be derived at build time. Files in _exhibits/ are generated by _python/update_exhibits.py and hand edits are overwritten, and the producer dashboard replaces _data/schedule.json wholesale, so neither side can gain a join field without changing a generator. The URL already in the schedule data is the key. Matching is on the SLUG INSIDE the URL, not on the URL, because the live data mixes three things a string compare would get wrong: - absolute and relative hrefs for the same page (https://www.makerfaireorlando.com/exhibits/high-noon/ vs /exhibits/willow-creative/) - category URLs (/exhibits/categories/power-racing/), which must match no exhibit — they normalise to "categories", which is nobody's slug - an href with no /exhibits/ segment at all, which normalises to "https:" or "" and likewise matches nothing An exhibit's own slug is page.slug, written into every generated file. Two passes. The first decides, once per event, whether this exhibit is in it — that is what dedupes the Nov 8 "Minecraft Makers" row, where the event url and both guests point at the same exhibit and a naive loop would print it three times.
